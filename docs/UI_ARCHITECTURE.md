# Product UI and remote Kit

Quadrant-Tasks owns task semantics, Branding, InboxItem, InboxPane, TaskRowShell,
all views and the MainWindow, QuickAddWindow and TaskEditorWindow contracts.
`ui/product/` holds Product DTOs, quadrant colors, timer typography, the Focus
breakpoint and eleven Product icon aliases. QuadrantTheme derives its values
from the imported Kit Theme.dark_mode; there is no second theme state.

The only shared UI source is the public Quadrant-Kit Git dependency pinned to
`838ecfbead2d0a1966907ddd742cb6f34516d3f6`, retained by the protected annotated
tag `candidate/extraction-838ecfbead2d`. The quadrant-ui build script maps
`@quadrant-kit` to the facade returned by `quadrant_kit::slint_library_path()`
and embeds static resources with EmbedFiles. Generated Rust window and model
types stay local to quadrant-ui. No sibling checkout is needed.

The Agent owns persistence and contains no Slint/Kit dependency. The GUI uses
IPC, has no storage/SQLite dependency, and uses Kit only while building Slint.
Gallery development belongs to the separate Quadrant-Kit repository.

## Checks

Use the pinned Rust 1.94.1 toolchain and Python 3.11 or later. The declared
Rust minimum remains 1.92.0; CI also builds both application binaries with it.

```console
python -m unittest discover -s scripts/tests -v
python scripts/check_ui_boundaries.py
cargo fmt --all --check
cargo clippy --workspace --all-targets --all-features --locked -- -D warnings
cargo test --workspace --locked
cargo build --locked --release -p quadrant-agent -p quadrant-app
```

On macOS use `TMPDIR=/tmp cargo test --workspace --locked`. The native socket
name includes the test profile path; Darwin's default long temporary directory
can exceed sockaddr_un capacity. Tests still use their own UUID directories and
never use the application profile. CI uses this short temporary root as well.

The guard checks Product export signatures/defaults, imports and cycles, static
asset ownership and MIT hashes, copied Kit declarations, build mapping, Cargo
overrides and the actual target-filtered resolved source/dependency graph.
`--target` selects a different target triple for graph checks. Its Slint scanner
fails closed on unsupported public syntax; compilation remains required.
The Rust host baseline covers current facade reexports and public shell method
headers, not arbitrary Rust syntax or behavior. Kit body fingerprints detect
unchanged and renamed copies; review must still reject rewritten generic copies.

The 23 original Product export signatures survive the cutover; four Product
semantic globals are added. Baselines under scripts are reviewed contracts,
never automatically regenerated by CI. Changes to defaults, APIs, Kit revision
or the build mapping require an intentional baseline and source review.

## Packaging and regression scope

The three platform packaging scripts build both companions with --locked,
verify the Product guard, and include GPL and Fluent icon MIT notices. The
--skip-build/SkipBuild option requires matching prebuilt binaries. Native build
hosts are required; the macOS archive remains unsigned. Release automation
requires the selected source commit to equal the existing version tag.

Phase 4 validates integration and synthetic native windows. Fresh no-sibling
checkouts, package resource closure and isolated-profile dual-process business
regression are the separate Phase 5 gate. Synthetic UI probes do not access a
database or start the Agent.
